# 每日简报（重庆大学）

把散落在各处的东西整合成一份每天早上推送的简报：

- **校内通知** —— 教务处 / 学院 / 图书馆等站点的网页通知
- **校外竞赛** —— 竞赛通知
- **QQ 群消息** —— 采集到的群消息（默认全抓，可按关键词过滤）
- **今日天气** —— 来自 [wttr.in](https://wttr.in)，无需 API key

四个部分交给大模型整理成一段**纯文本**，按类分组推送，每条给出标题 / 时间 / 地点 / 要求（原文没有的写「未提及」）和源链接；群消息额外带群号与发布者 QQ 号。

除了每天定时推给你自己，指定群里的**任何人都能主动来查**一份现算的简报（见[谁能指挥它](#谁能指挥它)）。

## 摘什么，由模型判断

抓到的通知不是照单全收。提示词里写明了**只留在校本科生相关的**：能报名的活动、竞赛、讲座、文体比赛、志愿服务；评奖评优；选课考试学籍；宿舍食堂校园卡网络水电校内交通医疗安全这类生活后勤。

人事任免、招标采购、财务审计、基建修缮、会议纪要、党务巡视、科研项目申报、学报与学术委员会、校友基金会、离退休工会这类行政公文由模型略去。**拿不准就留下**——宁可多一条，也别漏掉学生真用得上的。

判断依据是通知的标题**和正文**，所以 `fetch_body_campus` 建议保持开启。

两处兜底：

- 模型调用失败 / 超时 → 降级成纯列表，**且不过滤**，把抓到的全列出来（宁可多给，不可漏掉）
- 模型跑通但一条没留下 → 输出「今日无与学生相关的新通知」，**不会**倒回去把刚筛掉的公文列出来

**本插件不含任何登录态**，只抓公开网页 + 监听群消息。

## 安装

放进 AstrBot 的 `data/plugins/` 目录，然后**在面板点「重载插件」或重启 AstrBot**。

注意：插件目录只在启动时扫一遍，热重载也只认启动时就已注册的插件。所以**光把文件夹拷进去、不重载，列表里是不会出现的**——这一点很容易踩。

依赖见 `requirements.txt`（`httpx`、`beautifulsoup4`），多数 AstrBot 实例自带。

## 配置要点

| 配置项 | 说明 |
|---|---|
| `push_time` | 每天推送时间，默认 `09:00` |
| `push_targets` | 推送到哪。私聊和群都行：私聊形如 `<平台ID>:FriendMessage:<QQ号>`，群形如 `<平台ID>:GroupMessage:<群号>`，平台 ID 通常是 `aiocqhttp`（以你面板里的平台名为准）。**在目标会话里发 `/digest register` 自动登记**，一般不用手填 |
| `command_allow_from` | 管理员 QQ 号，可用**全部**指令。**默认是空的，即谁都不能用**——必须先填上自己的号 |
| `command_allow_groups` | 开放查询的**群号**。名单里的群里任何人都会用 `/digest`（只能查，用不了管理指令）。**默认留空 = 群里谁都不能查** |
| `query_cooldown_seconds` | 公开查询的冷却秒数，默认 `120`。同一个会话短时间内只现算一次，期内再来直接返回上次那份 |
| `llm_provider` | **可留空**。留空即跟随 AstrBot 的全局默认模型；只有想给简报换个更便宜的小模型时才在这里指定 |
| `weather_city` | 默认 `Chongqing` |
| `fetch_body_campus` | 校内通知默认**抓正文**——「时间/地点/要求」基本只在正文里，模型也要靠正文判断相关性 |
| `group_allow_from` | 只采集这些群的消息，填群号。**留空 = 机器人所在的每个群都抓**；填了则其他群的消息一律不入库 |
| `group_keywords` | 留空 = 群里的消息全要；填了则只保留含关键词的消息。这是按**内容**筛，不区分群 |

## 谁能指挥它

两个名单，管的事不一样：

| | 填什么 | 能干什么 | 留空时 |
|---|---|---|---|
| `command_allow_from` | **QQ 号** | 全部指令，包括 `/digest now`、`register`、`last` | 谁都不能用 |
| `command_allow_groups` | **群号** | 群里**任何人**都能 `/digest` 现算一份看 | 群里谁都不能查 |

默认锁死是刻意的：插件的默认值会跟着仓库一起公开，若写成「留空即全开」，别人装完忘了配就等于把 `/digest now` 对外敞开——那玩意会烧 API 额度、还会往群里发消息。

不在任何名单里的会话发 `/digest` 时，插件**一个字都不回**，并且会 `stop_event()` 把这条消息截断——不这样做的话，消息会继续流向别的插件和 AstrBot 的 AI 对话，机器人照样会在群里冒泡。

推送范围同理：`_push` 只遍历 `push_targets`，没登记过的会话一个字节都发不出去。机器人被拉进新群不会自动开口，得在那个群里发一次 `/digest register`。

### 群里的人能查到什么

`command_allow_groups` 名单里的群，任何人都可以 `/digest`，拿到的是**现算**的一份：

- **只含校内通知与竞赛**，不含群消息——群消息是跨群采集的，漏给别的群看等于把 A 群的聊天内容贴到 B 群
- 只看**最近 3 天**。查询走的是「没有已读基线」的路径，不按日期卡窗口就会把整站历史倒出来
- **不推送**：结果只回当前会话，不会进入 `push_targets` 的推送循环
- **不污染增量**：不写 `seen_ids`、不写 `digest_last`、不消费群消息缓冲，所以外人刷查询不会影响你自己那份简报到手的内容
- **限频**：同一会话 `query_cooldown_seconds` 秒内只现算一次，期内再来直接返回上一次的结果

公开查询和 `/digest test` 是两回事：`test` 是管理员的调试口径（全量、含群消息、不限频），只有 `command_allow_from` 里的人能用。

### 「看哪些群」和「发到哪些群」是两码事

两个方向各管各的，别混：

| | 管什么 | 配置项 | 留空时 |
|---|---|---|---|
| **收**（看） | 采集哪些群的消息 | `group_allow_from` | **全抓**——机器人所在的每个群都收 |
| **发** | 简报推到哪些会话 | `push_targets` | 一个都不发（只写 `digest_last`） |

- **只想盯某几个群** → 填 `group_allow_from`，比如 `["123456789", "987654321"]`。这是按**群号**筛；`group_keywords` 是按**内容**筛，两者可以叠加。
- **只让简报发到某几个会话** → 用 `/digest register` 登记（或手填 `push_targets`）。
- 收与发互不绑定：可以「收 3 个群的消息，只发到 1 个私聊」，这是默认推荐的用法。

> 注意「收」还隔着一层平台：机器人得**已经被拉进那个群、且 aiocqhttp 能收到该群消息**（群没禁言），插件这边才谈得上收。`group_allow_from` 是在「已经收得到」的前提下再筛一层。

## 手动修改指南

改东西有两个入口，**改完都要在面板点「重载插件」**（或重启 AstrBot）才生效——插件只在加载时读一次配置。

### 1. 在面板里改（推荐）

AstrBot 面板 →「插件」→ 每日简报 →「配置」。每一项都有中文说明，改完保存即可，`_conf_schema.json` 就是这张表单的定义。

### 2. 直接改文件（面板打不开时）

配置文件在实例目录下：

```
<实例目录>/core/data/config/astrbot_plugin_cqu_daily_digest_config.json
```

它按面板里的分组（推送 / 天气 / 大模型 / 抓取 / 安全 / 群消息）组织。常改的几项：

| 想改什么 | 改哪里 |
|---|---|
| 推送时间 | 「推送」→ `push_time`，24 小时制 `"HH:MM"` |
| 允许哪些 QQ 用指令 | 「安全」→ `command_allow_from`，是一个 JSON 数组，如 `["你的QQ号"]` |
| 开放哪些群来查 | 「安全」→ `command_allow_groups`，填**群号**数组，如 `["123456789"]`；留空 = 群里谁都不能查 |
| 查询限频 | 「安全」→ `query_cooldown_seconds`，默认 `120` 秒 |
| 推到哪些会话 | 「推送」→ `push_targets`（一般用 `/digest register` 自动写，不用手填） |
| 只采集哪些群 | 「群消息」→ `group_allow_from`，JSON 数组填群号，如 `["123456789"]`；留空 = 全抓 |
| 群消息按内容筛 | 「群消息」→ `group_keywords`，留空 = 全要 |
| 换简报用的模型 | 「大模型」→ `llm_provider`，留空即跟随全局默认 |
| 城市 | 「天气」→ `weather_city` |
| 竞赛是否抓正文 | 「抓取」→ `fetch_body_competition`，默认关 |

手改 JSON 时注意：**数组要写成 `["a", "b"]`，不能写成 `"a, b"`** 这种字符串——类型不对的配置项会被当成空值处理（白名单尤其如此，写错就等于把自己也锁在门外）。

### 3. 改抓取源

`sources.py` 里的 `SOURCES` 才是数据来源，加源方法见下一节。这个改的是插件源码，改完同样要重载。

### 4. 改「摘什么」的判断标准

「哪些算跟学生相关」写在 `digester.py` 顶部的 `SYSTEM_PROMPT` 里，是一段给模型看的自然语言。想调整保留/丢弃的范围，改这段文字即可，不用动代码逻辑。

改提示词时留个心眼：里面「固定五行、一行都不能少」这类**格式硬要求不要动**。曾经因为同时写了「每条最多 4 行」和「五行格式」两句自相矛盾的话，模型就会自作主张把「时间」「地点」两行省掉。改完记得用 `/digest test` 看一眼输出是否还有「时间：」「地点：」两行。

### 改完怎么验证

| 指令 | 用途 |
|---|---|
| `/digest test` | 立刻看简报长什么样，**不推送、不写去重记录**——调提示词最先用这个 |
| `/digest now` | 真跑一次并发出去 |
| `/digest last` | 看最近一次真正推出去的原文 |
| `/digest sources` | 看每个源配好没有 |

改配置 / 提示词不生效，九成九是**忘了重载插件**。

## 指令

| 指令 | 作用 | 谁能用 |
|---|---|---|
| `/digest`（或 `/digest query`） | 现算一份发到当前会话（只含校内通知与竞赛，最近 3 天，限频） | 管理员 + 开放群里的任何人 |
| `/digest help` | 使用说明 | 同上 |
| `/digest now` | 立即跑一次完整流程并推送 | 管理员 |
| `/digest test` | 看完整简报（含群消息）长什么样，不推送、不写去重 | 管理员 |
| `/digest last` | 查看最近一次推送的原文 | 管理员 |
| `/digest sources` | 查看信息源配置状态 | 管理员 |
| `/digest register` | 把当前会话登记为推送目标 | 管理员 |
| `/digest unregister` | 取消当前会话的登记 | 管理员 |
| `/digest targets` | 列出全部推送目标 | 管理员 |

「管理员」= `command_allow_from` 里的 QQ；「开放群」= `command_allow_groups` 里的群。两个名单之外的会话，发什么都是静默。

## 加一个信息源

编辑 `sources.py`，往 `SOURCES` 里加一个 dict：

```python
{
    "key": "cqu_xxx",              # 唯一标识，改了它该源已推条目会重推
    "name": "重庆大学XXX",          # 简报里显示的名字
    "url": "https://...",          # 列表页
    "selector": "ul.list li a",    # 命中列表里每条条目的 CSS 选择器
    "parser": parse_text_content,  # 从标签里抠标题的函数，见 parsers.py
    "category": "campus",          # campus | competition
    "base_url": "https://...",     # 相对链接补全用
    "excerpt_selector": "p.desc",  # 可选：列表页自带的摘要节点（省一次详情页请求）
    "article_selector": "div.v_news_content",  # 可选：详情页正文容器
}
```

`article_selector` **强烈建议配**。不配的话抓正文会退回整页文本，前 1500 字全是导航菜单（「搜索 旧版入口 基金会…」），跟正文毫无关系。配了之后容器没命中就宁可返回空串，也不退回整页。

`excerpt_selector` 的摘要可能是链接的**兄弟节点**而不是子节点（如 `<a class="title">…</a><p class="desc">…</p>`），插件会先在本条目里找、再往上一层父节点找。

加完用 `/digest test` 验证选择器有没有命中（`/digest sources` 会列出还没配 URL/selector 的源）。

## 首次运行行为

第一次跑（`seen_ids` 为空）**只会把当前抓到的条目记为基线，不推送**——否则第一次会把整站历史一次性刷给你。之后再跑推的就是真正的增量。
